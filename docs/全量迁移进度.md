## 原项目自身的边界

- 原 `acp` 是状态占位、退出码 2；Python 保持显式“不支持”的状态，没有伪造编辑器服务。
- `remote.rs` 的 CCR 部分是配置/环境描述模块，并没有实际代理监听器；Python 也不宣称启动了代理。
- Recovery recipes 的原模块是可注入执行器的仿真；诊断 API 明确返回 simulation，不自动 rebase 或合并。
- 原主 MCP 执行器支持 stdio；WS/SDK/managed proxy 描述不等于真实可连接传输。Python 额外实现 HTTP/SSE。
- 25 个占位 slash 命令、builtin 示例空插件不计作真正的引擎功能。

### 对上一版缺口清单的纠正

源码核对确认：原 CLI 的 `CliOutputFormat` 只有 Text/Json，NDJSON 是 Python 新增接口，原版不存在需要照搬的 stream-json envelope。原 MCP 的 OAuth discovery、headersHelper 与 WS/SDK/proxy 仅有配置描述，不能把它们说成原版已有而 Python 缺失的完整网络执行器；Python 保留配置并明确拒绝静默忽略认证。原策略/审批台账没有统一挂入所有任务，lane_completion 也标为 dead_code；迁移保留评估接口，不虚构自动合并执行链。

- Worker：补齐 `wrong_target`、错任务回显、`expected_artifacts` 检查；授权弹窗准确提取工具名与允许范围；长提示预览保留原版省略号。事件新增原版 `seq` / `timestamp` 及带 `type` 的结构化 payload，保留旧 Python 字段兼容网页。

- 真实执行：同一 Worker 的发送、重启、终止、超时诊断串行化；并发发送只启动一个任务；任务启动失败保存 `failed/protocol`；重启会取消真实执行任务，不能在任务仍运行时伪造完成。

- OAuth：真实 loopback HTTP 授权服务器验证 302 跳转、S256、换码、刷新令牌轮换、应用重建后读取凭据、拒绝授权、重放 state、刷新失败保留凭据。应用回调经 ASGI TestClient 测试，未使用云厂商账户登录。

验收：Windows 全量 **240 passed / 1 skipped**（符号链接权限），Ruff 与 Vue 构建通过。新增 111 项自动测试；79 项是参数化 Worker 场景，不能理解为 79 个新功能。冻结 Worker 夹具由原 Rust `WorkerRegistry` 实际执行生成，比较生命周期字段、事件序列和类型 payload；排除生成 ID、路径、时间、人工描述文案和健康摘要的来源文案。27 个 CLI 错误案例中 26 个错误分类/退出码/提示存在性与原版一致；未知顶层参数刻意直接报 `unknown_option`，原版会当提示词继续到凭据检查。不复制这个隐式模型调用行为。

### 尚不能宣称的内容

本轮完成了上述明确功能缺口的实现和验收，但没有宣称每个 CLI 文案、全部 55 工具输出字段、所有 Worker 屏幕异常组合都与 Rust 字节级一致。Python 使用 SQLite 会话库，导入原会话生成副本而不覆盖原文件；Web/流事件使用 Python 接口。OAuth PKCE/刷新已有自动化协议测试，尚未使用某个云厂商的真实 OAuth 用户账号完成交互登录。这些边界与证据分开记录，不能把可运行、目录覆盖或测试数量当成无条件完全等价。

Python 保留更严格的路径限制、运行预算、未知隔离请求拒绝、密钥屏蔽和完整历史存档。Windows 无 Linux namespace 能力，当前非特权容器也不支持嵌套 unshare；不伪造隔离成功。
